Before editing, read:

## Repository guardrails

- Keep this repository as the public GitHub profile surface.
- Do not turn the profile into RTS core, RTS-AGE, a product repository, or an operations log.
- Do not add private context, sensitive personal details, customer information, or internal operational material.
- Do not add secrets, API keys, tokens, credentials, or private links.
- Do not overclaim production readiness or commercial completeness.
- Keep public-facing claims concise, stable, and easy to verify.
- Prefer linking to canonical repositories over duplicating their documentation.

## Profile editing boundary

- Treat README edits as public positioning changes.
- Prefer minimal wording changes over broad rewrites.
- Keep the canonical RTS repository easy to find.
- If a project is experimental, describe it as experimental or omit it.
- If a link is unstable or not maintained, do not add it to the public README without review.

## Documentation rules

- Separate public positioning from internal operating notes.
- Keep profile maintenance notes under `docs/`.
- Do not place working drafts, customer-facing offers, or private planning material in the root profile README.

## Validation

- For documentation-only changes, report changed files and confirm that no private context, operations log, customer data, secret, product implementation, or canonical RTS data was added.
- Check public links when changing the README.
